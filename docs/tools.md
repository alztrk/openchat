# Workspace tools

The local Rust service provides read-only `list_files`, `search_files`, `read_file`, and `get_file_info` tools to ChatGPT Responses and OpenCode's OpenAI Chat Completions endpoint. They are exposed in every conversation and the provider chooses when to call them. The global Settings option `Onay İste` is the default: each valid tool call waits for a one-time user decision, and the service restricts canonical paths to the attached project folder or OpenChat's existing local data directory at `%LOCALAPPDATA%\Zihora`. The model can use project-relative paths, `project:/...`, or the retained `zihora:/...` data alias; without a project, bare relative paths resolve under `%LOCALAPPDATA%\Zihora`. The service resolves and revalidates the target after approval, including symlink resolution. `Tam erişim` skips approval and accepts absolute paths to existing folders or files anywhere. It also accepts `desktop:/...`, which resolves to the current user's OS-provided Desktop directory. The Desktop alias is rejected in `Onay İste`. Both modes use the same read-only tools; neither can edit files or run commands.

Both adapters translate provider tool definitions, calls, and results through OpenChat's shared Rust schema. ChatGPT Responses and OpenCode Chat Completions JSON stay inside their respective adapters; Flutter receives the same chat stream events from either provider. Adding another provider still requires an adapter for that provider's native protocol.

Tool calls are processed locally and their results are returned to the same provider before its final response. A single response is limited to six tool-call rounds, sixteen calls, and 16 KiB of serialized arguments per call. Unsupported, invalid, or out-of-scope requests return an explicit tool error. In `Onay İste`, a denial returns a permission error to the model without running the requested operation; approval applies only to that call. Stopping a response also clears its pending approval. Treat text read from the active tool root as untrusted content.

In `Onay İste`, each valid call emits `chat.tool.permission.requested` with its approval ID, tool name, canonical target path, and arguments. Flutter returns the one-time decision with `chat.tool.permission.respond`; a bounded in-memory broker connects that decision to the waiting request. Each call also emits shared `chat.tool.updated` activity for approval waiting, execution, and its result or denial. The desktop UI shows the tool name, target path, JSON arguments, and JSON output or error under the assistant message. Tool activity is saved with local chat history, so it remains visible after reopening a conversation and is included in Markdown conversation exports.

## Search behavior

- Searches skip dot-hidden paths and common generated or dependency directories by default: `.dart_tool`, `.gradle`, `.next`, `.nuxt`, `build`, `coverage`, `DerivedData`, `dist`, `node_modules`, `Pods`, `target`, and `vendor`.
- Selecting one of those directories directly as the search path includes it and its contents. `includeHidden` includes hidden paths; explicitly selecting a hidden path also includes its contents. The service does not parse `.gitignore` patterns yet.
- Searches return at most 40 matches per call. Each call walks the current filesystem directly; it does not build or depend on a persistent or in-memory workspace index. It scans at most 100,000 files, 100,000 directories, or 128 MiB of file contents per query. A `truncated` result means the scan did not finish.
- To keep common searches responsive, the first `limit + 1` files are searched serially so a full result page can return early. If that does not fill the page, the remaining files are scanned on at most eight workers. Results are merged in traversal order, preserving offsets across pages. The worker set and candidate list are bounded by the file and byte limits.
- `list_files` walks the current directory on each call. It retains only the first `offset + limit` eligible names in a max-heap, then sorts that retained page, instead of sorting the entire directory. It scans at most 100,000 entries.
- `read_file` skips bytes before the requested starting line without allocating a string for every skipped line. It returns at most 500 lines and 64 KiB, and refuses files larger than 64 MiB. `get_file_info` and `read_file` share the metadata read used to validate the file.
- Search and listing output remain compact and bounded. In `Onay İste`, returned paths use `project:/...` or `zihora:/...`; in `Tam erişim`, they are absolute. The `desktop:/...` input alias resolves only inside the current user's Desktop directory. Symbolic links in directory listings are skipped, and invalid or inaccessible entries set `truncated` or return an explicit error.

`list_files` returns at most 100 entries. `read_file` reports the continuation line when its line or byte cap stops the response.
