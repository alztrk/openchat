# Project instructions

OpenChat can apply project-specific instructions to conversations attached to a project. Edit them from the project's options, or create `.openchat/instructions.md` in the project folder and write UTF-8 Markdown instructions there. OpenChat reads the file when a new response run starts and sends its contents with that run's provider request.

The file is optional. A missing or whitespace-only file adds no project instructions. The editor enforces a 16 KiB UTF-8 byte limit and saves through an atomic replacement. Invalid UTF-8, read failures, and paths that resolve outside the attached project stop the request with a clear error; OpenChat does not silently ignore a configured but invalid file.

The text is saved in the run checkpoint so a resumed run keeps the instructions it started with even if the file changes later. Start a new run to apply edits. Project instructions are sent to the selected provider as part of the prompt, so keep them free of secrets and data that should not leave the device.

Project instructions apply only within their project context. They do not replace the user's current request or OpenChat's higher-priority instructions. In project options, set the currently selected provider/model route and reasoning effort as that project's default, or clear the project default. New conversations started from that project use its saved route when the referenced provider connection and model remain available; otherwise, OpenChat uses the global default. If a provider request fails, its error remains visible. A saved reasoning effort is applied only when the selected model still advertises it; otherwise, the provider's default reasoning behavior remains in effect. The model picker labels a route currently inherited from the project so its precedence over the global default is clear. Existing conversations keep their saved route. The local preference stores provider, model, reasoning effort, display name, and connection identifiers, never API keys or OAuth credentials. Since preferences are stored outside the conversation database, they are not included in database/profile archive exports.

Projects can provide reusable Skills in `.openchat/skills/<id>/SKILL.md`, where `<id>` starts with a lowercase letter and contains only lowercase letters, digits, and hyphens. OpenChat discovers up to 32 Skills and allows each project to select which ones apply. Skill files are limited to 16 KiB each and 64 KiB total per request. Skill selection is stored in local application preferences, outside the repository and conversation database. Selected Skill contents are sent with new provider requests; a pending user-question run retains the Skill text from its initial request. Project options show the Skill contents, and removed selections remain visible until cleared. Missing or invalid selected files stop the request with an error rather than silently omitting the instructions. Skills must use UTF-8 and resolve inside the project; symlinked Skill directories and files are rejected.

Shared preferences are managed in Settings, project instructions in `.openchat/instructions.md`, and project Skills in `.openchat/skills/<id>/SKILL.md`. The project Skills dialog previews each discovered source, while the project-instructions editor shows the project's direct instruction source. These preferences are sent to the selected provider as prompt content, so keep them free of secrets and data that should not leave the device.

An optional project index can be managed from project options. It stores bounded, redacted text excerpts in the local application cache, follows `.gitignore`, and only adds matching excerpts to a new request when enabled. Synchronize it after project changes; clear removes its local index data.
